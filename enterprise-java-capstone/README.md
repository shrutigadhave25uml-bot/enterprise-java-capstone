# Enterprise Java Full Stack Capstone — CarePoint

CarePoint is a responsive hospital appointment management demo built with Spring Boot, Spring Security, Spring Data JPA, H2, HTML5, CSS, and JavaScript. The frontend is served by Spring Boot and calls the REST API using `fetch()`.

> Educational capstone starter, not a production hospital system. Do not enter real patient data.

## Features
- Responsive hospital dashboard
- Create, list, view, update, and delete appointments via REST
- Bean Validation on request bodies
- Centralized JSON exception responses with `@RestControllerAdvice` / `@ExceptionHandler`
- Swagger UI and OpenAPI specification
- H2 file-backed database for local demo
- Spring Security HTTP Basic authentication for API routes; health, static frontend, and API documentation are public
- Architecture and setup documentation

## Architecture

```text
Browser (HTML5 + CSS + JavaScript)
          | fetch / JSON over HTTP
          v
Spring Security Filter Chain (HTTP Basic for API)
          |
          v
REST Controllers
          |
          +--> Bean Validation
          +--> GlobalExceptionHandler (@RestControllerAdvice)
          |
          v
Spring Data JPA Repository
          |
          v
H2 Database (./data/hospitaldb)
```

## Requirements
- JDK 17+
- Maven 3.8+
- Web browser

## Run locally
From the extracted project directory:

```bash
mvn spring-boot:run
```

Open:
- Frontend: http://localhost:8080/
- Health check: http://localhost:8080/api/health
- Swagger UI: http://localhost:8080/swagger-ui.html
- OpenAPI JSON: http://localhost:8080/v3/api-docs

The demo uses HTTP Basic authentication for API routes. Default Spring Security credentials are generated by Spring Boot and printed to the terminal on startup. For a simple local demo, copy the generated password from the console and use username `user` in the browser/API client when prompted. Do not deploy the default setup as-is.

## REST API

Base path: `/api/appointments`

| Method | Path | Description | Success |
|---|---|---|---|
| GET | `/api/appointments` | List appointments | 200 |
| GET | `/api/appointments/{id}` | Get one appointment | 200 |
| POST | `/api/appointments` | Create appointment | 201 |
| PUT | `/api/appointments/{id}` | Update appointment | 200 |
| DELETE | `/api/appointments/{id}` | Delete appointment | 204 |
| GET | `/api/health` | Health check | 200 |

Example POST JSON:

```json
{
  "patientName": "Priya Sharma",
  "doctorName": "Dr. A. Mehta",
  "department": "Cardiology",
  "appointmentDate": "2026-11-15",
  "status": "SCHEDULED"
}
```

For update, use the same fields. Dates must use ISO format `YYYY-MM-DD`.

## Error response example

A missing appointment returns HTTP 404 with a JSON body similar to:

```json
{
  "timestamp": "2026-10-26T10:00:00Z",
  "status": 404,
  "error": "Not Found",
  "message": "Appointment 999 was not found",
  "path": "/api/appointments/999"
}
```

Validation errors return HTTP 400 and include a `validationErrors` object.

## Authentication note
This capstone uses HTTP Basic to demonstrate authenticated API calls and a server-managed session policy. If your course requires JWT specifically, merge the JWT configuration from your separate Spring Security JWT project and update the frontend to store/send the Bearer token securely. For production, prefer a reviewed authentication design, HTTPS, managed secrets, authorization rules, audit logs, and privacy controls.

## Postman/manual API testing
In Postman, set Basic Auth username to `user` and use the generated Spring Boot password printed in the terminal. Test GET, POST, PUT, DELETE. You can also use Swagger UI to inspect the endpoint schemas and send requests.
